A directory’s listing is taken once when it is opened, so entries do not shift between readdir calls on the same handle.

Rename returns EEXIST when RENAME_NOREPLACE is set and the target exists, and EINVAL for any other flag, such as RENAME_EXCHANGE. On macOS every rename flag returns EINVAL. Renaming a directory onto a file returns ENOTDIR, and a file onto a directory EISDIR.

Python’s mount() raises OSError before mounting: EINVAL for a protocol no backend provides, and FileNotFoundError for a mount point that does not exist.

Writes¶

A file opened for writing is held in memory in full until it is closed. Writes and reads through that handle use the memory copy, and stat reports its size. Two handles open for writing on the same file each hold their own copy, and the last one closed wins.

Object stores keep no directories of their own. A directory created through a writable mount, or left empty after its last file is deleted or moved, stays visible in the mount until rmdir removes it or the mount ends. Renames on object stores copy and then delete, so they are not atomic.

Mount table¶

Read-only mounts use the ro option. On Linux, /proc/mounts lists the URL as the source and fuse as the type.

Inodes¶

Each path gets an inode number the first time it is looked up. Numbers are not reused, so a mount that visits many paths keeps a growing table for its lifetime.
